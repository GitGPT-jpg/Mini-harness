# 本地恢复存储与升级

本说明对应存储协议 v3。恢复验收的实际测试结果另见本轮交付记录；机制说明不代表所有平台均已验证。

## 支持范围

目标是同一宿主、同一运行目录的多进程协调。当前允许 macOS APFS/HFS 和 Linux ext/XFS/Btrfs；本轮实际运行环境为 macOS/APFS、Node 24.21.0。项目要求 Node ≥22.19.0，使用内置 `node:sqlite`，不需要外部数据库服务。

Windows、NFS、SMB、FUSE、overlay、tmpfs、未知文件系统和多宿主共享运行目录会受阻。Linux 分支不等于 Linux 实机验收。进程树取消覆盖正常继承进程组的后代；主动创建新 session/逃逸进程组的程序不属于自动取消保证范围。

## 权威数据与写入者

| 事实                          | 权威来源                                                           | 写入者与约束                                                |
| ----------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------- |
| TaskSpec/TaskContext          | Run 内的规范化输入、来源、确认与验收配置                           | 创建入口；发现本身不授予候选命令执行资格                    |
| Run、round、attempt、revision | `state.json`                                                       | 当前有效调度者；同一代也必须检查预期 revision               |
| 执行权                        | `lease.json`、`.lease-generation`                                  | 当前 owner/generation；续租不得复活过期代次                 |
| Operation 意图与取消请求      | `operations/<opId>/operation.json`                                 | 获得控制权的宿主；取消绑定 operation 身份                   |
| 真实执行身份及结果            | `runner.json`、`entity.json`、`command-result.json`、`result.json` | 独立 runner；不得修改 Run 或宣布任务完成                    |
| 原始证据                      | operation 的 stdout/stderr、结果与各轮验收产物                     | 执行者产出；结果消费必须核对身份与完整性                    |
| UI                            | 服务端状态与证据的投影                                             | 页面不能根据 HTTP 200、租约成功或 PID 存活宣布恢复/停止成功 |

`.run-lock.sqlite` 只承担该 Run 的互斥和迁移登记，JSON 仍是业务权威数据。不要删除、替换或单独复制锁数据库来“解锁”。

SQLite `BEGIN IMMEDIATE` 覆盖读取、条件检查及文件提交，锁等待最多五秒；使用 DELETE journal、`synchronous=FULL` 和 `fullfsync=ON`。最外层同步调用结束关闭连接；进程崩溃后由操作系统释放锁，不回收 TTL 锁文件。模型、长命令、工作区内容扫描不能放在锁中。

文件提交先写独立临时文件并 fsync，再原子替换目标并 fsync 目录。读者得到完整旧版或新版。多个 JSON 文件没有整体回滚能力，因此结果消费与对应 Run 阶段变化必须放在同一次 `state.json` 提交中。租约与 Run 的中间状态应受阻并重新核对，不能推断为新任务。

## 旧数据升级与回滚

1. 停止旧版 Harness 写者。已启动的旧协议 operation 缺少可信 boot/nonce，不能直接升级为可自动取消的新操作；先在旧版或人工核验后收尾。不要同时运行新旧二进制写同一目录。
2. 备份整个运行目录及会话数据，保留所有 `.cas.*`、锁残留与日志。本任务不会自动迁移用户日常服务的数据。
3. 新版第一次写某个 Run 或显式恢复时，在 SQLite 锁中执行一次性迁移。启动还会检查缺失 `state.json` 的旧目录（最多 1,000 条、总预算 5 秒、每次锁等待 500 ms），使唯一 CAS 副本恢复后可见；列表轮询不触发迁移。输入先备份至 `.storage-backup-v3`，备份包含内容和来源映射；校验 run ID、schema、代次、revision、状态和写者身份。
4. 目标缺失时，仅恢复唯一、完整且无冲突的候选；相同副本可去重。多个不同记录不按 mtime 或较大 generation 自动选择。迁移失败保留原件和备份，禁止自动执行。
5. 成功登记 `.storage-version` 与数据库协议记录后才允许新协议写入。不要把协议标记手工降低，也不要让旧版重新打开升级目录。

旧程序不会因为新增标记而自动获得围栏。检测到旧活进程会拒绝升级，但无法约束之后被人为重新启动的、不识别新协议的二进制。若必须回滚，应先停止所有新版宿主与相关执行实体，使用升级前完整备份和独立目录；不能只替换一个 `state.json`。

## 用户操作

1. 从「新任务」选择验收方式、能力包和实际工作目录。代码验收任务在原有命令栏填写验证命令；顶层命令与扩展 inputs 同值可合并，不同值会明确报冲突。发现的脚本候选仍需用户确认。
2. 按预览中的缺口补齐输入。修改目录、命令或配置后等待预览更新；开始执行时服务端仍会重新归一化、解析配置和核对内容身份。
3. 关闭页面不等于停止任务。正常长命令由独立 runner 持有日志及结果；重新打开页面后，从任务台查看原任务，不要新建同一任务来代替恢复。
4. 同版本服务异常退出后，用原运行目录启动新版服务，再从任务详情核对恢复资格。恢复会重新取得控制权并观察原 operation；提示「已取得控制权」并不表示任务已通过验收。没有可信执行结果时保持 unknown，不自动重跑。
5. 从任务操作发起停止后，先看停止请求是否受理，再看是否确认退出。未确认时继续核对同一任务；重复停止不会创建新执行。只有可信实体退出证据齐全时才显示已确认停止。
6. 代码验证通过后，仍按原配置执行指标、硬约束和模型评审。评审请求发出后宿主崩溃、未留下结果时，会停在评审异常；用户可检查证据后显式重试评审，或在产品允许时选择仅按代码验证收下。两者验收含义不同。

升级旧协议数据请先执行上面的升级步骤；不要用日常服务数据直接运行测试命令。

## 内容身份与异常处理

执行指纹读取实际 cwd 的内容，包含 tracked、staged、unstaged、untracked、执行权限和支持范围内的链接，并绑定当前能力包与验收配置。默认每文件 8 MiB、每遍 128 MiB、10,000 个条目、15 秒；双遍扫描不一致时有界重试。读取失败、超限、子模块、越界链接及不稳定内容返回受阻，不算“未变化”。

凭据目录不读取，普通产物和缓存默认排除。命令里明确的字面量脚本路径（例如 `python build/validator.py`）自动纳入，包括忽略目录中的文件。复杂 shell 仍兼容，但不能自动推断任意动态加载路径；这些依赖需通过现有 `inputs.validatorPath/configPath` 等显式声明。显式声明不能覆盖敏感排除。命令输出与模型总结分开保存。

任务列表只读扫描最多 10,000 个目录条目、单状态 16 MiB、累计状态 64 MiB，并在条目边界检查 1 秒预算；超限或损坏返回错误，HTTP 为 503，不伪装成空任务台，也不据此批准重复任务。列表不计算 Git/内容指纹。同步文件系统调用本身无法被 JavaScript 的时间预算抢占，慢盘仍可能超过该预算，网络文件系统不受支持。

遇到以下状态时：

- `unknown` 或身份不匹配：查看原 operation 的意图、握手、结果和 runner 日志；不要删除记录、补造 PID 或直接重跑。
- 环境变化：核对实际 workspace、验收命令、能力包与输入，确定哪些证据失效后再决定下一步。
- 已请求停止但未确认：后续只能继续核对原 operation 的退出，不得显示已停或创建替代执行。
- 锁等待或存储错误：保持受阻，排查本地磁盘与同目录写者；不要绕过公共提交函数。

## 基础回归

在 `pi-web-ui` 目录执行：

```sh
npx vitest run tests/unit/loop-storage-f1.test.ts tests/unit/loop-operation-f3.test.ts tests/unit/loop-fingerprint-f4.test.ts tests/unit/loop-inputs-f5.test.ts
```

测试使用隔离目录和本地可核验命令。基础模块测试不等同完整服务重启、浏览器、真实模型或真实集群验收；完整完成链、停止链及工程检查以本轮实际证据为准。
